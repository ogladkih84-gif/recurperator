# BMLC-175A: диагностика запуска BLDC

Новый скетч: [BMLC175A_v10_diag.ino](firmware/BMLC175A_v10_diag/BMLC175A_v10_diag.ino).
Исходный файл пользователя сохранён без изменений в [reference](reference/BMLC175A_v09m_REDOWNLOAD.ino).

Это **диагностическая версия с принудительной коммутацией**, а не законченный
sensorless-регулятор. Работу на двигателе ещё нужно проверить. Параметры ШИМ и разгона
оставлены как в присланном скетче, чтобы сравнение имело смысл.

## Что обнаружено в исходнике

* Таблица шестиступенчатой коммутации корректна: один верхний и один нижний ключ
  разных фаз. Нижние D11/D10/D9 имеют аппаратный ШИМ; программный ШИМ не нужен.
* Датчики ЭДС используются только для записи при отключённом мосте. Во время
  вращения положение ротора не измеряется. Поле может уйти вперёд ротора, а
  программа продолжит переключения: рывки не доказывают ошибку таблицы.
* Шаг 100 мс соответствует 50 об/мин поля, 20 мс — 250 об/мин, 10 мс — 500 об/мин
  при двух парах полюсов ротора. Это расчётная скорость поля, не измеренная скорость
  ротора. Один сектор соответствует 30 механическим градусам; на малых оборотах
  ступенчатость момента может быть заметна.
* В RAMP→HOLD исходник сбрасывает lastStepUs без коммутации. Это способно удлинить
  один сектор почти на дополнительный период. В новой версии срок сохраняется.
* Ручные s/m после теста задерживают начало записи выбега. Теперь b запускает
  запись автоматически сразу после HOLD, с прежним ожиданием 2 мс после отключения.

## Распиновка взята из рабочего скетча

| Сигнал | Nano classic, ATmega328P / 16 МГц |
|---|---|
| Верхние U / V / W через NPN, HIGH = включён | D7 / D4 / D2 |
| Нижние U / V / W, аппаратный PWM | D11 / D10 / D9 |
| Делители ЭДС U / V / W | A3 / A2 / A1 |
| Виртуальная нейтраль | A0 |
| Потенциометр | A4 |
| Кнопка на GND, INPUT_PULLUP | D8 |

Распиновка присланного кода расходится с текстовыми подписями Pin на рисунке.
Перед загрузкой сверить фактический монтаж именно с таблицей выше.
Timer1 и Timer2 заняты ШИМ; Timer0 обслуживает время Arduino. Servo/tone и библиотеки,
перенастраивающие эти таймеры, добавлять без переработки нельзя.

## Проверка на макете

1. Открыть новый `.ino` в Arduino IDE. Выбрать Arduino Nano / ATmega328P; для старого
   загрузчика при необходимости Processor → ATmega328P (Old Bootloader).
   Прошивать с отключёнными 12 В силового моста.
2. Проверить монтаж, общую землю и ограничение тока БП. Ток подбирать по допустимым
   параметрам двигателя и ключей. Прошивка не ограничивает ток и не обнаруживает
   остановку ротора. При выраженных рывках или большом токе сразу послать `s`.
3. Serial Monitor: **115200**, окончание строки Newline. Для сравнения оставить
   потенциометр в прежнем положении; диапазон ШИМ сохранён 20..30%.
4. Послать `i20`, затем `b`. Тест: ALIGN 250 мс → RAMP 6 с → HOLD 2 с → отключение
   моста → запись выбега около 0,77 с. Дождаться `CAPTURE COMPLETE`, послать `d`.
5. Сохранить CSV. Если тест приемлем по току и ротор не теряет синхронизацию,
   сравнить с `i15` и `i10`. Не увеличивать мощность вслепую при рывках.
6. Для противоположного направления: `s`, дождаться полной остановки, затем `v`
   или короткое нажатие D8. После предыдущей работы минимум 5 с до запуска в другую
   сторону. Пауза **не подтверждает остановку**, её контролирует оператор.
   Затем `b` или `t`. Нажатие кнопки при работе игнорируется.

| Команда | Действие |
|---|---|
| `t` | Тест без автоматической записи, затем отключение |
| `b` | Тот же тест, затем автоматическая запись выбега |
| `s` | Отключение моста, также прерывает запись |
| `i10` … `i40` | Конечный сектор в мс, только при остановленном управлении |
| `m` | Запись с отключённым мостом; ротор можно вращать вручную |
| `d` | CSV последней записи, только после завершения/остановки |
| `v` | Переключить направление следующего теста, только в STOP |
| `?` | Параметры и максимальное опоздание планировщика |

Планировщик не выдаёт серию догоняющих шагов. Если опоздание достигает целого сектора,
он отключает мост и сообщает `COMMUTATION DEADLINE MISSED`. Это контроль программы,
не контроль синхронизации ротора. После разгона сектор HOLD становится заданным i.

## Осциллограф Rigol DS1054

Земли обычных щупов соединены между собой и с PE. Все зажимы земли — **только GND
схемы**, при совместимом заземлении БП. Не подключать землю щупа к фазе или +12 В.

Для первого снимка: CH1=A3 (делитель U), CH2=A0 (нейтраль), CH3=D7 (верхний U),
CH4=D11 (нижний U). Щупы ×10 с правильной настройкой каналов. MATH=CH1−CH2.
Начать с 20 мс/дел для общей картины при i20; отдельно 5 мкс/дел для ШИМ.

Нужны два участка: конец RAMP/начало HOLD и начало выбега после отключения.
В свободной фазе сравнить форму и пересечения U−N с переключениями ключей.
На выбеге искать повторяющуюся последовательность U−N, V−N, W−N, а не только шум.
CH3/CH4 показывают команды Arduino; они **не доказывают**, что MOSFET успевает
закрыться. Достаточность DEAD_US=100 проверять отдельно по затвор–исток, для верхнего
ключа — дифференциальным измерением с учётом источника на +12 В.

ШИМ 31,37 кГц имеет период 31,9 мкс и импульсы примерно 6,4–9,6 мкс при 20–30%.
Если силовой ключ не успевает нормально открываться за это время, изменение периода
коммутации не исправит проблему. Требуется измерение реальных фронтов.

CSV: `us,U,V,W,N,U-N,V-N,W-N`. 128 наборов, шаг 6 мс, фактическая отметка начала набора
с точностью 100 мкс. Каналы считываются последовательно, два analogRead на канал:
весь набор занимает примерно 0,8–0,9 мс. Для высоких оборотов такая запись недостаточна.
Буфер 1280 байт; статические данные новой сборки — 1622 из 2048 байт SRAM,
оставшиеся 426 байт используются стеком. Динамическая память в скетче не выделяется.

## Проверки в среде разработки

`python scripts/build_avr.py` собирает настоящий ELF/HEX под ATmega328P, используя
AVR GCC и ядро Arduino AVR. Пути задаются `AVR_PREFIX` (каталог с bin) и `ARDUINO_AVR`
(каталог с cores/variants). В текущей среде установлен локальный комплект Debian:
GCC AVR 14.2.0, Arduino AVR core 1.8.7. HEX выдаётся во временный каталог, указанный сборкой.

Логика отдельно проверяется на модели Arduino, без имитации электрической части:

```sh
g++ -std=c++17 -Wall -Wextra -I tests/fake_arduino tests/diagnostic_test.cpp -o /tmp/bldc-diagnostic-test
/tmp/bldc-diagnostic-test
```

Проверяются таблица, команды, сохранение срока RAMP→HOLD, автоматическая запись,
метки времени, пауза и порядок реверса, остановка при пропуске срока и отмена записи.
Компиляция и модель не подтверждают устойчивый запуск реального двигателя.
Следующий этап — настройка разгона по CSV/осциллограммам и переход к коммутации по ЭДС.
